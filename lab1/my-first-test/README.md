## Юу хийсэн бэ

Энэ төсөл нь `https://www.saucedemo.com/` демо дэлгүүр дээр Playwright ашиглан гурван UI автомат тест бичсэн.

- **Амжилттай нэвтрэх**: `standard_user / secret_sauce` мэдээллээр нэвтрээд `Products` гарчиг болон URL-ийг шалгана.
- **Амжилтгүй нэвтрэх**: буруу нууц үгээр нэвтрэхэд алдааны текст гарч, хуудас үлдэхийг шалгана.
- **Бараа сагслах**: бараа нэмж, сагсны тоо `1`, сагсны хуудас болон `Your Cart` гарчигт очихыг шалгана.

Тестүүд [saucedemo.spec.ts](./tests/saucedemo.spec.ts) файлд байна. Амжилттай нэвтрэх тестүүдийн төгсгөлд logout хийнэ. Сөрөг тест нь бие даан ажилладаг учир нэвтрэх шаардлагагүй.

## Locator ба Trace

Элемент олоход `getByRole`, `getByPlaceholder`, `getByText`, `locator` зэрэг Playwright locator ашигласан. XPath ашиглаагүй нь DOM бүтэц болон CSS class өөрчлөгдсөн ч хөндөгдөхгүй, хэрэглэхэд илүү ойлгомжтой тестийн гол шалтгаан юм.

Playwright config дээр trace, видео болон алдааны үед screenshot цуглуулах тохиргоо ашигласан. Тест ажиллахад `test-results/` фолдерт trace болон видео үүснэ. `npx playwright test --trace on` тушаалаар trace-ийг хүчээр нээж ажиллуулж болно.

Амжилттай давсан тестийн бусад шалгуураас `test-artifacts/passing-trace-demo.zip` файлд trace хадгалагдсан. Ижил тестийн `test-artifacts/passing-test-video.webm` нь бичлэгийн нотолгоо юм.

## Selenium-тэй харьцуулсан ажиглалт

Playwright нь Selenium-тэй харьцуулахад auto-wait механизмаар элемент бэлэн болохыг автоматаар хүлээдэг тул хэрэгжүүлэх явцын explicit wait-г багасгадаг. Playwright-ийн `npx playwright install` тушаал хөтчүүдийг нэг төвтэй суулгаж, олон хөтөчийн туршилтыг нэг тестийн хүрээнд зохицуулж чаддаг. Codegen нь үйлдэл бичихэд хурдан бөгөөд trace viewer алхам бүрийн DOM snapshot, сүлжээний мэдээллийг үзүүлдэг. Selenium нь илүү matured ecosystem, олон хэлний өргөн дэмжлэг, одоо мөрдөж буй enterprise системд нийцдэг давуу талтай. Гэхдээ хөтөч бүрт driver бие даан суулгаж, explicit wait тодорхойлох шаардлага нь Playwrightээс илүү код бичихэд хүргэдэг. Аль алины лиценз Apache 2.0 тул сонголт нь төслийн орчин, багийн туршлага, debugging хэрэгцээнээс хамаардаг.

## AI ашигласан тухай

Тестийн алдааг засахдаа AI-р санаануудыг жишиг болгож үзээд, сонирхсон locator болон assertion-уудыг өөрөөр шалгаж зассан. AI-аар үүссэн кодыг шууд хуулалгүй, `getByRole` болон `getByPlaceholder`-ийг хэрэгтэй элементүүдэд нь сонгож, нэвтрэлт болон logout үйлдэл бие даасан тест бүрд ажиллах ёстойг нягталсан.
